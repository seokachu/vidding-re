## 1. 권한 모델 — 관계 판정

사용자 유형(role)이 없다. **경매와 나의 관계**가 화면과 권한을 정한다.

| 관계 | 조건 | 할 수 있는 것 |
|---|---|---|
| **주최자** | 내가 등록한 경매 | 수정 · 삭제(사연 0건일 때) · 공감(+50) · 채팅 |
| **참여자** | 내가 사연을 쓴 경매 | 사연 수정 · 삭제 · 추가 입찰 · 공감(+10) · 채팅(낙찰 시) |
| **방문자** | 로그인, 위 둘 다 아님 | 열람 · 사연 작성(쓰는 순간 참여자로 전이) · 찜 |
| **비회원** | 미로그인 | 열람만. 그 외 액션은 로그인으로 유도 |

- 관계는 계정 속성이 아니라 **경매마다 따로** 정해진다. 사용자가 선언하지 않는다
- 같은 상세 화면이 관계에 따라 셋으로 갈린다 — 방문자·참여자·주최자 (S03 · S03b · S04)
- 화면 진입은 프록시가 막고, **데이터 권한의 최종 판정은 RLS가 한다**

상세: [00-관계-판정](./specs/00-관계-판정.md)

## 3. 기능별 명세

각 기능의 원본 스펙은 **기능명 · 목적 · 동작 방식 · 예외 처리 · 완료 조건** 5항목으로
작성돼 있다. 여기서는 현행 기준의 핵심만 요약한다.

### F1. 경매 등록

- 사진(필수 1장) · 제목 · 설명 · 기간(1 · 3 · 7일)으로 등록한다. 마감 시각은 등록 시점 + 기간
- 수정은 주최자만, **사연이 1건이라도 있으면 삭제할 수 없다** — 남의 입찰을 증발시키지 않는다
- 이미지는 Storage 버킷에 사용자별 폴더로 올린다 (RLS로 남의 폴더 접근 차단)

### F2. 경매 탐색

- 홈(S01)은 최신 경매를, 목록(S02)은 검색과 정렬(최신 · 마감 임박 · 사연 많은 순)을 제공한다
- 마감 임박(1시간 이내)은 배지로 구분한다. 상태 배지는 진행중 · 마감 임박 · 마감됨 · 낙찰됨 · 유찰

### F3. 사연 작성·입찰

- 사연(텍스트)과 함께 포인트를 걸어 입찰한다. **경매당 사연 1건**, 포인트는 추가 입찰로 올릴 수 있다
- 마감 전 삭제는 **전액 반환 + 재작성 허용**. 마감 후에는 낙찰 사연만 삭제 불가
- 가입 시 5,000 P 지급. 추가 획득 경로는 **경매를 열어 낙찰시키는 것**뿐

### F4. 공감

- 사연에 공감을 남기면 가중치가 총점에 더해진다 — **참여자 +10, 주최자 +50**
- 사연당 1회, 자기 사연에는 불가. 마감 뒤에는 공감 버튼이 잠긴다

### F5. 낙찰

- pg_cron이 1분 주기로 마감을 처리한다. **총점 = 건 포인트 + 받은 공감 가중치**, 동점이면 먼저 작성한 사연
- 정산: 낙찰자 차감 확정 → 주최자에게 이전, 미낙찰자는 전액 반환. 사연 0건이면 유찰
- 정산은 포인트 원장으로 기록되고, **"반환 + 이전 = 차감 총액"이 깨지면 롤백**된다

### F6. 1:1 채팅

- 낙찰이 확정되면 주최자–낙찰자 채팅방이 열린다. Supabase Realtime으로 실시간 수신, 읽음 표시
- 낙찰자는 저장된 배송지를 **카드 형태 메시지로 전송**할 수 있다 (보내기 전 확인 다이얼로그)
- 연결이 끊기면 상태 줄로 알리고, 재연결 시 놓친 메시지를 다시 불러온다. 전송 실패는 재전송 제공

### F7. 찜하기

- 목록 · 상세에서 하트로 저장하고, 마이페이지 찜 탭에서 모아 본다. 비회원은 로그인 유도

### F8. 마이페이지

- 프로필(닉네임 · 아바타는 마지막 로그인 제공자를 따른다) · 보유 포인트 · 배송지
- 탭 3개: 내 경매 / 내 사연(참여중 · 낙찰 · **미낙찰** 배지) / 찜
- 포인트 내역(S15)은 원장 그대로 — 가입 축하 · 입찰 · 반환 · 낙찰 수령

### F9. 알림 (+ X1 · X2 · X3)

- 종류: **마감 임박**(기간에 비례한 3단계 — 3일 · 1일 · 1시간 전) · **새 사연**(주최자) · **낙찰 결과**(전원) · **새 메시지**
- 하단 탭에 미읽음 점, 목록을 열면 읽음 처리. 알림을 누르면 관련 경매 · 채팅방으로 이동
- **현행 확장**: 웹 · 앱 푸시로도 발송되고(X1 · X2), 화면을 보고 있으면 새로고침 없이 점이 켜진다(X3)
- 새 메시지 알림은 **내용 미리보기 40자**를 싣고 **방마다 최신 1건**만 남는다. 배송 정보는 개인정보라 미리보기하지 않는다

### F10. 인증

- 구글 · 카카오 소셜 로그인만 제공한다 (이메일 · 비밀번호 없음)
- 로그인이 필요한 곳에서 진입하면 **왜 왔는지 알리고, 로그인 후 원래 위치로 돌려보낸다**
- **접근 판정은 실제로 있는 화면에만 한다.** 프록시가 아는 경로 목록(`routes.ts` 의 `KNOWN_ROUTES`)에 없으면 판정을 건너뛰고 404(S17)로 흘려보낸다 — 없는 주소는 로그인해도 여전히 없어서, 막아 봐야 사용자를 두 번 헛걸음시킬 뿐이다
- 목록 안에서는 **막는 쪽으로 판정한다** — 어느 공개 규칙에도 안 걸리면 열지 않는다. 새 화면을 목록에 빠뜨리면 조용히 뚫리는 게 아니라 비회원에게 404 로 보인다(눈에 띄게 실패한다)
- 목록은 손으로 적지만 **어긋난 채로 오래 가지 않는다** — `pnpm check:routes` 가 `src/app` 의 실제 라우트와 양방향으로 대조하고(빠진 것 · 지웠는데 남은 것) CI 가 매 PR 에서 돌린다. 자동 생성하지 않는 이유는, 이 목록이 공개/보호 규칙 옆에서 **사람이 읽고 판단하는 값**이기 때문이다

### F11. 온보딩

- 로그인 전 3장: 사연으로 입찰한다 → 참여 방식 → 낙찰 규칙. 건너뛸 수 있다

### F12. 배송지 관리

- 1건만 등록 · 수정한다. 우편번호 검색 포함
- 용도는 **낙찰 후 배송 정보 전송**(F6) 하나다. 서버가 저장된 값을 다시 읽어 보내므로 클라이언트 위조가 불가능하다

### X1 · X2. 푸시 (웹 + 앱)

- `notifications` INSERT 트리거가 pg_net으로 `/api/push` 웹훅을 부른다. 발송 주소 · 시크릿은 Vault에 보관
- 웹은 VAPID 웹 푸시, 앱 셸(WebView)은 Push API가 없어 **Expo 토큰을 페이지에 주입**해 같은 테이블에 저장 — 발송 시 endpoint 모양으로 웹 푸시 / FCM을 가른다
- 구독은 알림 화면 배너에서 켜고 끈다. 계정 전환 시 이전 계정의 구독 행은 회수된다

### X3. 실시간 알림 배지

- `notifications` INSERT를 Realtime으로 구독해 서버 트리를 갱신한다 — 미읽음 수의 진실은 서버에 있으므로 클라이언트에서 따로 세지 않는다
- 알림 목록을 보는 중에 온 알림은 목록에 바로 나타나고 자동으로 읽음 처리된다
- 연결이 끊겼다 붙으면(절전 등) 한 번 갱신해 놓친 알림을 따라잡는다

### X4. 채팅 목록

- `/chat` — 상대 · 경매 제목 · 마지막 메시지 · 미읽음 수. 참여자 판정은 RLS 조회가 한다
- 탭 4곳 헤더 오른쪽에 진입 아이콘(+ 미읽음 점). 배송 정보 메시지는 목록에서도 미리보기하지 않는다

### X5. PWA 설치

- 웹 매니페스트로 "설치할 수 있는 앱" 요건을 갖추고, 탭 4화면에서 하단 탭 위에 **설치 유도 배너**를 띄운다
- 설치 흐름은 플랫폼별로 갈린다 — 크로미움(안드로이드 · 데스크톱 크롬/엣지)은 네이티브 설치 프롬프트, iOS는 "공유 → 홈 화면에 추가" 가이드 바텀시트
- 도울 수 없을 때는 나타나지 않는다 — 앱 셸 안, 이미 설치됨, 인앱 브라우저, 최근 닫은 사용자(7일)
- 스플래시는 잉크 블루 배경 + 흰 로고 + 태그라인 — iOS는 기기별 이미지 17장(`pnpm splash`로 생성), 안드로이드는 매니페스트에서 자동 생성
- **APK 앱 셸의 스플래시는 2단계다** — 프로세스가 뜨는 순간은 네이티브가 **배경색만** 보이고(`vidding-app` v1.3.2), RN 오버레이가 S00(로고 + 태그라인)을 웹 로드가 끝날 때까지 잇는다. 네이티브에 아이콘을 두면 아이콘은 정중앙 · RN 은 덩어리 중앙이라 인계 순간 로고가 23dp 튀었다 — 아이콘을 지우면 "튀는" 것이 "나타나는" 것이 된다
- APK 배포는 `/download` 페이지가 맡는다 — **인앱 브라우저(카카오톡 등)는 APK 설치가 막히므로** 감지해서 외부 브라우저로 자동 전환한다. README 의 QR 도 이 페이지를 가리킨다

### X6. 에러 처리 · 오프라인

- **404 (S17)** — 어느 라우트에도 걸리지 않은 주소와 `notFound()` 를 `app/not-found.tsx` 가 함께 받는다. 경매 상세처럼 자기 문맥이 있는 곳은 자기 `not-found` 를 그대로 쓴다
- 안내만 하고 끝내지 않고 **갈 곳을 함께 준다** — 홈 · 경매 목록 버튼과 빠른 이동 칩(채팅 · 알림 · 마이). 찾지 못한 주소를 그대로 보여줘 오타인지 고장인지 구분시킨다
- **앱(WebView)은 이 404 를 그대로 본다.** 앱 셸이 웹을 띄우는 구조라 앱용 화면을 따로 만들지 않았다 — 위에 네이티브 상태바만 얹힌다
- **오프라인 (S18)** — 서비스 워커가 설치 시점에 `/offline.html` **한 장만** 미리 받아 두고, 화면 이동이 네트워크 실패로 끊길 때 대신 돌려준다. 연결이 돌아오면(`online`) 자동으로 새로고침한다
- **페이지는 캐시하지 않는다.** 캐시가 늘수록 "고쳤는데 옛 화면이 뜬다"는 갱신 실패만 늘어난다. 화면 안의 조회 실패는 지금처럼 `ErrorState` 가 제 자리에서 다룬다
- 서비스 워커 등록을 알림 배너에서 **앱 시작 지점으로 옮겼다** — 푸시를 켠 사람만 오프라인 화면을 갖는 것은 이상하다. 등록은 권한을 묻지 않는다
- **앱 셸 (`vidding-app` v1.3.1)** — 지금까지는 로드가 실패하면 안드로이드 웹뷰의 내장 에러 페이지("웹페이지를 사용할 수 없음")가 그대로 떠서, 앱 안에서 브라우저가 튀어나온 것처럼 보였다. `renderError` 로 그 자리를 S18 화면이 대신 채운다
- **`renderError` 는 웹뷰를 대체하지 않는다.** react-native-webview 는 웹뷰와 `renderError()` 결과를 형제로 나란히 그리므로, 그냥 두면 내장 에러 페이지가 위에 남고 우리 화면이 그 아래로 밀려 화면 밖으로 나간다 (v1.3.0 의 버그). 오프라인 화면을 불투명 배경으로 컨테이너 전체를 덮게 해 가린다 — 에뮬레이터에서 네이티브 경로 · 서비스 워커 경로 둘 다 확인했다
- CTA 는 [다시 시도 = `reload()`] + [홈으로 = 웹뷰 재마운트]. `reload()` 는 실패한 주소를 다시 부를 뿐이라, 그 주소 자체가 문제일 때 빠져나갈 길이 하나 더 필요하다
- **연결 복구는 NetInfo 가 아니라 도달 확인으로 잡는다.** 네이티브 모듈이 하나 늘어나는데 알려주는 것은 "링크가 붙었는가"뿐이라, Wi-Fi 에 붙었지만 밖으로 못 나가는 상태를 못 거른다. 오프라인 화면이 떠 있는 동안에만 `/offline.html` 을 4초 주기로 찔러보고(앱을 다시 켤 때도 한 번), 응답이 오면 자동으로 다시 불러온다. **새 네이티브 의존성은 없다**
- 아이콘은 벡터 라이브러리를 새로 들이는 대신 lucide 글리프를 `.pen` 색으로 구워 `assets/` 에 넣었다
- **비회원도 404 를 본다.** 예전에는 프록시가 모르는 경로를 전부 로그인으로 보내 이 화면이 비회원에게 닿지 않았다. 이제 프록시가 아는 경로 목록에 없으면 판정을 건너뛴다 (F10 참고) — 보호 경로의 로그인 유도는 그대로다
- **화면 오류 (S19)** — 404 는 "없는 주소", 이건 **있는 화면인데 못 그린 경우**다. 조회가 예외를 던지거나 렌더가 실패하면 `app/error.tsx` 가, 루트 레이아웃까지 깨지면 `app/global-error.tsx` 가 대신 선다. 없을 때는 Next 기본 오류 화면이 그대로 나왔다
- 화면 *일부*의 조회 실패는 여기까지 오지 않는다 — 그건 그 자리에서 `ErrorState` · `InlineRetry` 가 받는다 (F8 4 · F9 4). **빈 상태 · 조회 실패 · 화면 오류가 서로 다른 화면이다**
- CTA 는 [다시 시도] + [홈으로 가기]. **Next 16 은 `reset` 이 아니라 `unstable_retry` 다** — `reset` 은 오류 상태만 지우고 같은 데이터로 다시 그려서, 서버 조회가 원인이면 대개 그대로 또 터진다
- 서버에서 난 오류는 내용이 클라이언트로 넘어오지 않는다. 서버 로그와 맞춰볼 수 있는 `digest` 해시를 칩으로 보여줘 제보에 실어 보낼 수 있게 한다
- `global-error` 는 루트 레이아웃을 **대신하므로** `html` · `body` · 전역 스타일 · 390 셸을 직접 그린다. 폰트는 따라오지 않아 시스템 서체로 떨어진다 — 오류 화면 한 장을 위해 폰트 로딩을 다시 세우지 않는다
- 다만 **루트 레이아웃이 서버에서 터지면 첫 응답은 Next 의 내부 오류 문서(`<html id="__next_error__">`)다.** `global-error` 는 그 뒤 하이드레이션에서 그려진다 — Next 의 동작이고, 상태 코드는 500 으로 정확히 나간다 (로컬에서 확인)

### X7. 경매 자동 활성화

- **비어 있는 목록은 서비스가 아니다.** 포트폴리오로 열어 둔 서비스라 실사용자 유입이 없어, 며칠만 지나면 홈이 마감된 경매만 남은 화면이 된다. GitHub Actions 크론(`auction-daily.yml`, 하루 4회 — 09:20 · 12:20 · 16:20 · 20:20 KST)이 그 자리를 채운다
- 하는 일은 둘이다. **① 그날(KST) 새 경매가 없으면 1건 등록** — 풀(`scripts/data/auction-daily-pool.mjs`, 35건)에 안 올린 품목이 있으면 그것을, 없으면 **마감된 지 7일 지난 경매를 사진째 재등록**한다. 그래서 풀이 비어도 자동화는 멈추지 않는다
- **② 진행중 경매에 예정 시각이 지난 사연 · 입찰 · 공감을 그때그때 등록한다** — 한 경매가 올라온 직후엔 조용하다가 며칠에 걸쳐 반응이 쌓이는 것처럼 보인다. 하루 4회로 나눈 이유가 이것이다
- **테이블에 직접 쓰지 않는다.** 입찰 · 공감을 직접 넣으면 원장과 잔액이 어긋나 `close_auction()` 이 롤백된다. 매직링크로 로그인해 anon 키로 `place_bid()` · `toggle_episode_like()` 를 부르는 **실제 사용자 흐름을 그대로 밟는다** — RLS 를 통과하므로 정책이 바뀌면 이 스크립트도 사용자처럼 같이 막힌다 (`seed.mjs` 와 같은 원칙)
- 시드 계정 포인트가 모자라면 그 입찰만 건너뛰고 다음 실행에 재시도한다. 진행중 경매가 마감되면 반환 · 이전이 일어나므로 시간이 지나면 저절로 풀린다
- 마감 처리는 여기서 하지 않는다 — Supabase pg_cron 이 1분 주기로 이미 하고 있다 (F5)
- 의존성 없는 스크립트라 Actions 에서 `pnpm install` 없이 바로 돈다. `pnpm auction:daily --dry-run` 으로 계획만 볼 수 있다

## 6. 설계에서 달라진 것

v1.0 설계 문서는 수정하지 않고 그대로 보존한다. 아래가 **구현하면서 달라진 전부**다.

| 영역 | 설계 (v1.0) | 현행 (v2.0) | 이유 |
|---|---|---|---|
| 푸시 | **만들지 않는다** (F9) | 웹 푸시 + 앱 푸시 도입 (X1 · X2) | 서비스 밖에서도 마감 · 낙찰을 놓치지 않게. Vault · pg_net 트리거로 우려했던 관리 비용을 줄였다 |
| 알림 갱신 | 화면 진입 시 조회 | Realtime 실시간 배지 (X3) | 열어 둔 화면에서도 점이 켜져야 알림이 알림답다 |
| 채팅 진입 | 낙찰 알림에서만 | 채팅 목록 `/chat` + 전 탭 헤더 아이콘 (X4) | 알림이 밀리면 대화로 돌아갈 길이 없었다 |
| 채팅 알림 | 메시지마다 1건 | **방마다 최신 1건** + 내용 미리보기 40자 | 같은 방 알림이 목록을 도배했다. 배송 정보는 미리보기 제외 |
| 내 사연 배지 | 탈락 | **미낙찰** | 사연을 꺼낸 사람에게 탈락은 시험 낙방처럼 읽힌다. 포인트 내역의 어휘와 통일 |
| 배송지 | 경매 등록의 요건 | 요건 아님 — 낙찰 후 전송 용도만 | 등록 장벽을 없앤다. 배송지가 실제로 쓰이는 곳은 전송뿐이다 |
| 프로필 | 가입 시점 고정 | **마지막 로그인 제공자**를 따라간다 | 구글 ↔ 카카오를 오가도 아바타 · 닉네임이 어색하지 않게 |
| 앱 | 범위 밖 | Expo WebView 하이브리드 + FCM 푸시 | 웹 푸시가 닿지 않는 안드로이드 웹뷰를 앱 셸이 메운다 |
| 설치 | APK 배포뿐 | PWA 설치 배너 + 스플래시 (X5) | APK 를 받지 않아도 웹에서 바로 홈 화면에 앱처럼 설치되게 |
| 에러 화면 | 경매 상세의 없는 경매만 (F3 4.1) | 전역 404 · 오프라인 · 화면 오류 (X6) | 없는 주소는 Next 기본 404, 앱은 웹뷰 내장 에러 페이지가 떴다 — 서비스 밖으로 튕겨 나가는 두 자리였다 |
